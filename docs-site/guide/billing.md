# 计费、额度与并发

云端在每条请求链路上执行准入控制，并在响应完成后入账。

## 计费公式

模型价格单位为美元 / 百万 Token，数据库以百万分之一美元（micros）保存费用：

```text
输入费用 = 输入 Token × 输入单价
输出费用 = 输出 Token × 输出单价
总费用（micros） = 输入费用 + 输出费用
```

例如输入价格 `$2`、输出价格 `$6`，请求消耗 1,000 输入 Token 和 500 输出 Token：

```text
费用 = (1000 × 2 + 500 × 6) / 1,000,000 = $0.005
```

优先使用上游响应中的 `usage`。如果成功响应没有 usage，则使用字符数近似估算，因此严格结算场景应确保推理后端返回准确 usage。失败响应不会进行估算计费。

流式聊天请求会自动加入 `stream_options.include_usage=true`，以便兼容后端返回最终用量。

## Token 与费用额度

Key 同时支持两种上限，任一达到上限后，新请求返回 `429`：

- `token_quota`：累计 Token 上限；
- `budget_quota`：累计费用上限，美元。

`0` 表示不限制。额度在请求前检查，完成响应后更新，因此同时进行的请求可能使最终累计值略微超过阈值。

## 每分钟请求限制

`rpm_limit` 使用进程内 60 秒滑动窗口。超过限制返回 `429`，错误类型为 `rate_limit_error`。设为 `0` 表示不限制。

## 双层并发

并发控制分为两层，请求必须同时满足：

1. **Key 并发**：限制单个调用方同时执行的请求数；
2. **供应商并发**：限制本地节点同时执行的请求数。

并发从请求准入开始计算，到响应流结束或失败后释放。超过任一层限制返回 `429`。`0` 表示该层不限制。

建议先根据显存、连续批处理配置和实际延迟设置供应商并发，再为不同 Key 分配更小的公平份额。

## 多供应商选择

相同模型可配置在多个供应商下。云端过滤停用、离线和推理异常节点，然后按活动请求数排序，选择第一个未达到供应商并发上限的节点。

当前实现是单进程内的简单负载选择，不是跨区域调度器，也不会在流式响应中途切换到其他供应商。
