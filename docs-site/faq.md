# 常见问题

## 家中没有公网 IP，可以使用吗？

可以。`utoken` 主动向云端建立 WebSocket/WSS，云端只使用这条已有连接转发请求，不需要公网 IP、UPnP 或端口映射。

## 云端会主动连接我的 8080 端口吗？

不会。8080 等推理端口只由本地 `utoken` 访问，可以继续绑定 `127.0.0.1` 或内网地址。

## 支持 llama.cpp、vLLM 和 SGLang 吗？

只要它们提供 OpenAI 兼容 HTTP 接口即可。`utoken` 不管理推理进程，你需要先自行启动服务并确认 `/v1/models` 可用。

## 云端和本地各使用什么端口？

云端默认 `3000`，管理面板、公开 API 和 WebSocket 共用。`utoken` 出站连接云端，不需要监听公网端口；本机管理 API 默认只监听 `127.0.0.1:8787`。

## utoken up 会阻塞终端吗？

不会。它启动后台服务后立即返回。`utoken serve` 才是面向 systemd 的前台模式。

## stop 和 down 有什么区别？

`stop` 只停止供应商转发，保留本机 Web/API；`down` 会退出整个后台管理服务。停止后再次执行 `up` 可恢复。

## QML 启动后为什么提示无法连接后台服务？

QML 是附属控制端。先运行 `utoken up`，再运行 `utoken ui`。如果修改了管理端口，两边使用相同的 `--web-port`。

## API Key 和供应商凭据有什么区别？

`umo-agent-...` 只用于本地连接器接入云端；`umo-sk-...` 分发给模型调用方。不要把供应商凭据当作公开 API Key。

## 为什么在线节点在模型列表里，但请求仍然 429？

可能是 Key 或供应商并发已满，也可能是 RPM、Token 或费用额度达到上限。查看错误消息和请求日志可以确定具体限制。

## 费用如何计算？

按每个模型的输入/输出 Token 单价计算，单位为美元 / 百万 Token。优先使用上游 usage；成功响应缺少 usage 时会近似估算。

## 是否支持多云端进程？

当前不支持直接多进程共享运行。管理员会话、RPM、活动并发和隧道都在进程内，需要架构扩展后才能水平扩展。

## 如何修改本地管理端口？

```bash
utoken down
utoken up --web-port 8890
```

QML 同时使用 `utoken ui --web-port 8890`。

## 如何排查连接失败？

依次检查：

1. `utoken status` 和 `utoken logs`；
2. 云端地址是否使用正确的 HTTPS/WSS；
3. 供应商 ID 与凭据是否匹配、是否已轮换；
4. 本地 `curl http://127.0.0.1:8080/v1/models`；
5. 反向代理是否转发 WebSocket Upgrade，并关闭 SSE 缓冲；
6. 云端请求日志和供应商健康状态。
