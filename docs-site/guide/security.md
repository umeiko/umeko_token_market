# 安全与生产检查

## 凭据分类

| 凭据 | 用途 | 使用位置 |
| --- | --- | --- |
| `umo-agent-...` | 本地供应商接入云端 | 仅本地 `utoken` |
| `umo-sk-...` | 调用公开模型 API | 仅对应调用方 |
| 本地 API Key | 访问已有推理服务 | 仅本地 `utoken` |
| 管理员密码与 Cookie | 云端管理操作 | 仅管理员 |

云端只保存 API Key 和供应商凭据的 SHA-256 哈希。完整凭据仅创建或轮换时显示一次。

## 公网部署

- 必须启用 HTTPS/WSS，并设置 `COOKIE_SECURE=true`。
- 使用有效证书，不要在本地连接器中跳过 TLS 验证。
- 管理面板与公开 API 当前共用端口；如需限制管理来源，应在反向代理或防火墙中额外控制 `/api/admin/*`。
- 将 `TRUST_PROXY=true` 仅用于可信反向代理之后，避免伪造客户端 IP 影响登录限流。
- 持久化并备份 SQLite，限制数据库文件的操作系统权限。

## 本地边界

- Web 管理 API 只监听 `127.0.0.1`，不要将其暴露到公网或局域网。
- 推理服务可以继续只监听回环或内网地址，无需为云端开放入站端口。
- QSettings 中的供应商凭据和本地 Key 依赖操作系统用户目录权限保护。
- 不在日志、截图或公开 Issue 中分享完整凭据。

## 运营建议

- 每个用户或应用使用独立 API Key，便于限额、停发和审计。
- 根据显卡能力设置供应商并发，避免无限请求拖垮推理节点。
- 将云端请求超时与推理后端的最长生成时间一起评估。
- 定期检查失败日志、异常延迟、额度消耗和离线供应商。
- 使用单云端进程；若需高可用或多实例，应先外置会话、限流、并发和隧道状态。

## 数据隐私

请求日志不保存提示词与模型输出正文，但模型内容会经过云端和本地转发进程。部署方应根据数据敏感程度控制服务器访问、日志级别和备份权限。
